# Keitaro Wrapper (Adrobot T3)

Обёртка над рекламным трекером [Keitaro](https://keitaro.io): локальная копия кампаний, потоков и офферов с весами, в которой изменения готовятся локально (жёлтый поток), а в Keitaro публикуются по кнопке **PUSH TO KT**.

Реализованы обе части тестового задания:

1. **Создаватор кампаний** — Name + Geo (коды через запятую) + Offer (автокомплит) → в Keitaro создаётся кампания с доменом/группой/источником и двумя потоками: Flow 1 ловит указанные страны и редиректит на Google, Flow 2 отдаёт трафик выбранному офферу.
2. **Редактор офферов** — воспроизводит логику их обёртки из видео: FETCH STREAMS FROM KT, добавление/удаление офферов с пересчётом весов (сумма всегда 100), пины весов, removed-архив с BRING BACK, синхронизация после удаления офферов прямо в Keitaro, PUSH TO KT и CANCEL.

Стек: **FastAPI + SQLAlchemy 2 + Alembic + httpx**, фронт — статика (vanilla JS) без сборки. 57 тестов pytest проверяют веса, синхронизацию, фильтры, статистику, обработку ошибок, предпросмотр и независимость опубликованного состояния от черновика. Интеграция также проверена на настоящем Keitaro — границы проверки описаны ниже.

## Быстрый старт

```bash
git clone https://github.com/sv11-17gk/etolegko-keitaro-wrapper.git
cd etolegko-keitaro-wrapper
```

### Вариант 1 — Docker (демо без реального Keitaro)

```bash
docker compose up --build
```

Поднимаются два сервиса:

- **обёртка**: http://localhost:8000 — сразу открывает рабочий редактор кампаний
  (также доступен на http://localhost:8000/index.html),
  создаватор: http://localhost:8000/create.html, Swagger API: http://localhost:8000/docs;
- **mock-Keitaro**: http://localhost:8081 — фейковый Admin API с фикстурой тестовой кампании `campaign 2` (2 потока, 3 оффера с весами 33/33/34), как на скриншотах ТЗ. В демо режиме состояния mock-Keitaro живут в памяти процесса.

На `/` открыт редактор: выбор кампании, FETCH и таблица офферов. Скриншоты из ТЗ
использованы как визуальный ориентир, галереи в интерфейсе нет. Исходники и инструкция связаны с репозиторием
`https://github.com/sv11-17gk/etolegko-keitaro-wrapper`.

### Публичное демо на etolegko.porfiry.ru

`docker-compose.public.yml` запускает демо с mock-Keitaro. Обёртка слушает только
`127.0.0.1:18081`, mock доступен внутри Docker-сети. Настоящие доступы Keitaro для
этого запуска не нужны. VIEW IN KT открывает отдельное представление тестового
трекера: настройки кампании, потоки и опубликованные доли. REMOVE IN KT меняет
именно mock, не локальную копию обёртки; затем FETCH показывает удалённый оффер
в архиве редактора. В реальном режиме VIEW IN KT ведёт в настоящую админку.
Данные демо общие для посетителей. Mock хранит состояние в памяти; после его
перезапуска FETCH восстанавливает исходную тестовую кампанию. Созданные в mock
кампании после перезапуска теряются.

Для первого запуска на сервере DNS домена должен указывать на этот сервер.
Нужны Docker Compose, Nginx, Certbot, Git, curl и systemd. Установка выполняется
из опубликованной копии репозитория одной командой:

```bash
sudo bash deploy/install.sh
```

Скрипт использует `/srv/apps/etolegko-keitaro`, настраивает отдельный виртуальный
хост и включает проверку обновлений из GitHub каждые две минуты.

На сервере внешний прокси перехватывает HTTP-01 challenge: даже произвольный URL
`/.well-known/acme-challenge/<token>` возвращает ответ с ключом прокси.
Поэтому сертификат Let's Encrypt выпускается через DNS-01. При первом запуске
Certbot покажет TXT-запись `_acme-challenge.etolegko.porfiry.ru`. Добавьте её
в DNS-зону `porfiry.ru`, дождитесь распространения и нажмите Enter в Certbot.
После этого установщик продолжит настройку HTTPS. Для ручного DNS-01 продление
тоже требует TXT-проверки; автоматическое продление требует интеграции с DNS-провайдером.

После установки выпуск новой версии приложения — commit и push в `main`.
Доступы и локальные базы исключены из Docker-контекста.

### Вариант 2 — локально с реальным Keitaro

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# заполните KT_BASE_URL и KT_API_KEY (Профиль -> API ключи -> Создать новый ключ в админке Keitaro)
alembic upgrade head          # миграции (см. ниже)
uvicorn app.main:app --reload
```

Открыть http://localhost:8000.

## Миграции

Схема БД обёртки — [alembic/versions/0001_initial.py](alembic/versions/0001_initial.py): таблицы `kt_offer_cache` (кэш имён офферов), `campaigns`, `streams` (снапшот `published_offers`), `offer_bindings` (рабочая копия привязок).

```bash
alembic upgrade head                    # накатить все миграции
alembic downgrade -1                    # откатить последнюю
alembic revision -m "описание"          # создать новую миграцию
```

Подключение к БД задаётся переменной `DATABASE_URL` (SQLite по умолчанию). Для PostgreSQL дополнительно установите драйвер `pip install psycopg2-binary` и задайте URL `postgresql+psycopg2://user:password@host/database`. Проверки в этом решении проводились на SQLite. При старте приложения `uvicorn app.main:app` миграции накатываются автоматически.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest tests/ -q
```

57 тестов (in-memory, без внешней сети) покрывают:

- исходные веса из Keitaro сохраняются как получены (33/33/34); при локальном пересчёте трёх равных долей — 34/33/33, четырёх — по 25%; сумма всегда 100;
- пины: вес закреплён при удалении/возврате, пин сам по себе не желтит поток;
- remove → серый/0%/исключён из распределения; BRING BACK → возврат;
- CANCEL: непушенные добавления удаляются физически, остальное откатывается к снапшоту;
- FETCH после удаления офферов в Keitaro → у нас removed, не удаление;
- PUSH: в payload только активные привязки, блок при сумме весов ≠ 100, после push истина — Keitaro;
- создаватор: кампания с фильтром `country/accept/[MX, AU]`, Flow 2 с share 100, автоподстановка домена/группы/источника;
- полный сценарий из видео: add → yellow → push → удаление в KT → fetch → removed → bring back → pin.
- удаление последнего оффера в KT: пустой поток сохраняет архив и позволяет BRING BACK → PUSH;
- потерю ответа при создании: POST не повторяется автоматически, чтобы не создавать дубли; GET повторяется при временной ошибке;
- формат потоков настоящего Keitaro, обязательный тип группы `campaigns` и ссылку VIEW IN KT.
- повторную отрисовку карточки: один клик отправляет один запрос;
- BRING BACK → CANCEL и ADD из архива → CANCEL сохраняют архивную привязку;
- PIN сохраняет неравномерные опубликованные веса без изменения статуса потока;
- поток без офферов не разбирает фильтры и возвращается без их описания.

Тест JavaScript в `tests/test_frontend.py` использует Node.js. Если Node.js отсутствует,
этот тест отмечается как skipped; остальные проверки выполняются на Python.

Основания — [полное ТЗ](https://app.notion.com/p/mnovikov/Adrobot-2b01eb78a7bb80a1b188c3a4a1cad55e)

Локальное распределение воспроизводит этот порядок остатка.

| Первый поток перенаправляет выбранные страны на Google | Фильтр country/accept и HTTP-редирект подтверждены в настоящем Keitaro |

| Фильтр в шапке любого потока (уточнение v2) | Flow 1: country accept [MX,AU]; Flow 2 без фильтров: null, без «filter by None» |
| ADD меняет локальную копию, поток желтеет | Четыре доли по 25%, Keitaro обновляется по PUSH |
| CANCEL отменяет неопубликованное добавление | Новая привязка удаляется, исходные веса восстанавливаются |

| Удаление оффера в Keitaro → FETCH | Известная привязка сохраняется в removed, доступен возврат |

| Один клик — одна операция | Проверка четырёх действий после повторных отрисовок; CANCEL сразу откатывает черновик |
| Общая шапка Offer / Share / Stats / Trends / Actions | Пять согласованных колонок, PUSH/CANCEL под заголовком, ADD снизу |
| VIEW IN KT | Настоящая админка либо отдельное представление опубликованных данных mock |
| preview у оффера | Адрес preview_path из Keitaro; в демо явно обозначенный тестовый предпросмотр |
| SHOW ALL OFFERS | Каталог без обязательного поискового запроса, страницы и выбор целевого потока |
| Навигация и создание | Список кампаний, рабочие хлебные крошки, компактная форма Name / Geo / Offer |

### Границы воспроизведения интерфейса

На исходных скриншотах и в видео столбцы Stats и Trends пусты. По уточнению v2
Stats показывает клики оффера за сегодня, Trends — SVG-график за семь дней.
У removed-офферов в обеих колонках прочерк; при ширине меньше 640px Trends
скрыт CSS-ом, сохраняясь в DOM. Счётчик clicks today в заголовке получает данные
report/build. Сценарий SHOW ALL OFFERS в видео не
демонстрируется; в этом решении кнопка открывает полный каталог офферов с поиском,
пагинацией и добавлением в выбранный поток. Это явно принятое поведение, а не
подтверждение скрытой логики исходной программы. Модули основной системы AdRobot
(Creatives, Bundles и другие) находятся за пределами обёртки из задания.

Для проверки демо откройте редактор и VIEW IN KT рядом. Добавьте оффер: жёлтый
черновик не меняет соседнюю страницу трекера. Нажмите PUSH, обновите трекер —
появятся опубликованные офферы и веса. Нажмите там REMOVE IN KT, затем FETCH
в редакторе: известный оффер сохранится серым с 0% и BRING BACK. Демо-API
`/api/demo/...` возвращает 404 при DEMO_MODE=false; настоящего Keitaro эти
демонстрационные операции не касаются.

## Проверка на настоящем Keitaro

20 ноября 2026 года через код обёртки создана отдельная кампания `test_karin_wrapper_live_20261120` (ID `217138`). Подтверждены домен, группа, источник, два потока, фильтр `country/accept/[MX, AU]`, редирект Flow 1 на Google и Flow 2 с оффером 100%.

Результат публикации проверен отдельным GET из Keitaro. В конце проверки исходный состав собственного тестового потока восстановлен. Проверен также `report/build` с реальными строками статистики.

Из мобильной формы создана вторая кампания `test_karin_wrapper_ui_20261120` (ID `217145`), настройки обоих потоков сверены отдельным запросом к Keitaro. Интерфейс проверен на ширинах 1280 и 390 пикселей. После сверки с референсами редактор открывается сразу на `/`; на телефоне общая таблица прокручивается внутри рабочего блока, сохраняя пять колонок. Повторно проверены создание из формы, автокомплит, PUSH, CANCEL, архив и сохранение пина при пересчёте. Ссылка VIEW IN KT ведёт на карточку `/admin/#!/campaign/{id}/main`.

У выданного аккаунта доступен только один оффер, создание новых возвращает 403. Поэтому добавление второго оффера и перераспределение весов между несколькими офферами проверены локальными тестами. Для полного прогона этих операций на Keitaro нужны минимум два доступных оффера.

## Как работает модель синхронизации (коротко)

- У потока есть **снапшот `published_offers`** — что реально лежит в Keitaro после последнего fetch/push. Рабочая копия — таблица `offer_bindings`.
- **Жёлтый поток** (`dirty`) = рабочая копия ≠ снапшот. Белый = совпадает.
- **ADD/REMOVE/BRING BACK** меняют только рабочую копию и пересчитывают веса (непиннутые делят `100 − сумма пинов` поровну, целочисленно, остаток — первому по порядку). **PIN/UNPIN** меняет закрепление без пересчёта текущих весов.
- **PUSH** шлёт в `PUT /streams/{id}` только активные привязки `{offer_id, share, state:"active"}` и блокируется, если сумма ≠ 100. После push делается контрольный GET: Keitaro — истина.
- **CANCEL** удаляет физически привязки непушенных добавлений и восстанавливает снапшот.
- **FETCH** синхронизирует с KT: пропавшие в KT офферы становятся `removed` (серые, с BRING BACK), вернувшиеся — восстанавливаются; непушенные добавления стираются.
- Потоки без офферов (Flow 1, редирект) не получают редактор офферов. По уточнению v2 их фильтры сохраняются и отображаются в шапке.

## Статистика офферов (уточнение v2)

`GET /api/streams/{kt_stream_id}/stats` возвращает все известные привязки офферов
потока, включая removed. Несуществующий локальный поток — 404. Пример:

```json
{"stream_id":564221,"offers":[{"offer_id":3749,"clicks_today":12,"week":[6,9,7,11,10,14,12]}]}
```

`week` содержит ровно семь целых значений от старого дня к сегодняшнему;
пропущенные дни заполняются нулями. На офферный поток выполняется один запрос
отчёта за семь календарных дней, включая сегодня. Редактор переиспользует эти
данные после PIN/Remove/Bring Back; новый неизвестный оффер обновляет отчёт
потока. Ошибка отчёта возвращается как 502 и показывается прочерком с пояснением,
не превращаясь в вымышленные нули и не блокируя редактирование.

Mock принимает `group_by: ["offer_id"]` и `stream_id`, сохраняя прежний отчёт
по потокам. Его сид даёт 12/8/10 кликов у 3749/3717/11111 и суммарно 30 у Flow 2;
у созданных потоков значения нулевые. В реальном режиме используются
`dimensions: ["offer_id", "day"]`, `measures: ["clicks"]` и фильтр stream_id
из [контракта Admin API](https://admin-api.docs.keitaro.io/). Выданный инстанс
отклоняет дополнительный ключ group_by, поэтому group_by/stream_id верхнего
уровня отправляются только в DEMO_MODE. Реальный запрос проверен на собственном
тестовом потоке и принят сервером; в нём нет кликов, поэтому непустые ряды
проверены детерминированным сидом и тестами парсера.

## Решения и допущения (важно)

1. **`schema`/`action_type` потоков.** На выданном Keitaro проверены `redirect`/`http` для редиректа и `landings`/`http` для офферного потока. URL редиректа передаётся строкой в `action_payload`. Значения схем/действий доступны через переменные окружения.
2. **Остаток целочисленного деления весов.** FETCH сохраняет полученные от Keitaro веса. Локальные операции отдают остаток первому непиннутому офферу, как в видео ETOLEGKO на 5:46 (38/37 при закреплённых 25%).
3. **PUT `offers` заменяет привязки целиком** (PUT в Keitaro частичный по остальным полям). Поэтому push шлёт полный набор активных офферов с весами.
4. **`report/build`** — формат `rows` в OpenAPI не зафиксирован; парсер защитный (dict-строки и list-строки с `meta`). Если реальный формат отличается, клики в шапке просто покажутся как «—», остальное не пострадает.
5. **Группы.** Список запрашивается с обязательным `type=campaigns`. Числовой `group_id` проверен при создании кампании на живом инстансе.

## Структура

```
app/
  main.py            FastAPI + автоматический alembic upgrade на старте
  config.py          настройки (pydantic-settings, .env)
  db.py, models.py   SQLAlchemy 2: campaigns, streams, offer_bindings, kt_offer_cache

  api/routes.py      REST /api/... + раздача ошибок Keitaro как 502 с телом ошибки
frontend/            index.html (редактор на / и /index.html), create.html,
                     campaigns.html (список), demo-keitaro.html (только mock),
                     css/, js/ — vanilla JS, без сборки
mock_keitaro/        фейковый Admin API для демо и тестов
alembic/             миграции
tests/               pytest + mock Keitaro через starlette TestClient
```
